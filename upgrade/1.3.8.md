# report_activities 1.3.8

Build: `2026110500`  
Requires: Moodle 4.0 (`2022041900`)  
Supported: Moodle 4.0 to 5.2 (`[400, 502]`)  
Maturity: Stable

Moodle Report Builder plugin that adds grade data sources for custom reports.

## What the plugin offers

This plugin does not create a separate report screen. It adds data sources inside Moodle Report Builder (`/reportbuilder/index.php`).

You can build custom reports with columns, filters, conditions, audiences, schedules and CSV/Excel export using Moodle core features. The plugin only supplies the sources and grade fields.

Install path:

- Moodle 4.x: `report/activities`
- Moodle 5.1+: `public/report/activities`

## Compatible Moodle versions

| Moodle | PHP used in CI | What works |
|--------|----------------|------------|
| 4.0 | 8.0 | Activities and Final grade sources. No course-category entity (core added it in 4.1). |
| 4.1, 4.2, 4.3, 4.4 | 8.0 or 8.1 | Both sources, including course category. |
| 4.5 | 8.1 | Both sources. |
| 5.0, 5.1 | 8.2 or 8.3 | Both sources. |
| 5.2 | 8.3 and 8.4 | Both sources. Reference version for this release. |

Moodle 3.x is not supported. Report Builder does not exist there.

## Report sources

### 1. Activities

- One row = one student × one graded activity
- Uses gradebook items with `itemtype = mod` (Quiz, Assignment, graded Forum, Lesson, Workshop, SCORM, and any other `mod_*` that writes grades)
- Does not list pages, files, URLs, labels or other activities without grades
- Does not use category totals as rows

Available fields include:

- User (name, email, profile fields)
- Course and course category (category from Moodle 4.1+)
- Activity name and activity type
- Raw grade (from the activity module)
- Final grade of that activity (from the gradebook)
- Percentage
- Grade on a 0–10 scale
- Feedback
- Last modified date

Default Activities columns:

1. User full name with link
2. Course full name with link
3. Activity name
4. Activity type
5. Percentage
6. Grade 0–10 (half up: 7.3 becomes 7, 7.5 becomes 8)
7. Final grade

### 2. Final grade

- One row = one student × one course
- Uses the course gradebook total (`itemtype = course`)
- Same value shown as Course total in the grader report
- Uses Moodle `grade_get_course_grades()` so weights, formulas and aggregation are already applied
- The plugin does not recalculate the total

Available fields include:

- User
- Course and course category (category from Moodle 4.1+)
- Final grade (course total)

## Important difference

- Use **Activities** when you need grades per activity
- Use **Final grade** when you need the course total only
- The course total is not mixed into the Activities source

## Access control

- Capability: `report/activities:view`
- Required to see and use both sources (`is_available()`)
- Also checked on the plugin entry page
- Allowed by default for managers and course creators
- Privacy: null provider (reads core tables only; stores nothing)

There is no link under **Site administration / Reports**. That entry only redirected to Report Builder and was removed in this release.

Open **Reports / Report builder / Custom reports**, choose **New report**, then the source **Activities** or **Final grade**.

## How to use

1. Install into `report/activities/` (or `public/report/activities/` on Moodle 5.1+) and run site upgrade
2. Open **Site administration > Reports > Report builder**
3. Create a new report
4. Choose source **Activities** or **Final grade**
5. Add columns, filters, audience and schedules as needed

## Upgrade

Copy the plugin in place and open **Site administration / Notifications**, or run:

```bash
php admin/cli/upgrade.php
```

On Moodle 5.1 and later:

```bash
php public/admin/cli/upgrade.php
```

No database tables are created or changed. There is no `db/upgrade.php` savepoint for this release.

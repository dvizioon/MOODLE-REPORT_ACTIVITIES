# report_activities 1.3.8

Release `1.3.8` (build `2026110500`). Stable.

This plugin does not add its own report screen. It registers two **Report Builder** data sources. Columns, filters, access, schedules and CSV/Excel export stay in core Moodle (`/reportbuilder/index.php`).

## Compatible Moodle versions

Declared in `version.php`:

| Field | Value |
|-------|-------|
| `$plugin->requires` | `2022041900` (Moodle 4.0.0) |
| `$plugin->supported` | `400` to `502` |
| `$plugin->release` | `1.3.8` |

| Moodle | PHP used in CI | What works |
|--------|----------------|------------|
| 4.0 | 8.0 | Activities and Final grade sources. No course-category entity (core added it in 4.1). |
| 4.1, 4.2, 4.3, 4.4 | 8.0 or 8.1 | Both sources, including course category. |
| 4.5 | 8.1 | Both sources. |
| 5.0, 5.1 | 8.2 or 8.3 | Both sources. |
| 5.2 | 8.3 and 8.4 | Both sources. Reference version for this release. |

Moodle 3.x is not supported. Report Builder does not exist there.

Install path:

- Moodle 4.x: `report/activities`
- Moodle 5.1 and later: `public/report/activities`

## How the plugin works

Each graded activity already has a gradebook item (`grade_items`, `itemtype = mod`) and a student grade (`grade_grades`). The **Activities** source reads those rows and exposes them in Report Builder.

| Context | Examples |
|---------|----------|
| User | Full name, email, ID number, profile fields |
| Course | Full name, short name, category (Moodle 4.1+) |
| Activity | Name, type (Quiz, Assignment, …), max and min grade |
| Grade | Raw grade, final grade, percentage, grade 0-10, feedback |

The **Final grade** source reads the course total (`grade_items.itemtype = course`). The number shown in the cell comes from `grade_get_course_grades()`, so category weights are already applied.

Default Activities columns:

1. User full name with link
2. Course full name with link
3. Activity name
4. Activity type
5. Percentage
6. Grade 0-10 (half up: 7.3 becomes 7, 7.5 becomes 8)
7. Final grade

Open **Reports / Report builder / Custom reports**, choose **New report**, then the source **Activities** or **Final grade**.

There is no link under **Site administration / Reports**. That entry only redirected to Report Builder and was removed in this release.

Capability: `report/activities:view` (system context). Without it the sources are hidden.

Privacy: null provider. The plugin does not store personal data. It only reads `user`, `course` and `grade_*`.

## What changed in 1.3.8

- Removed the **Activities reports** item from Site administration / Reports.
- Declared support for Moodle 4.0 through 5.2 in one codebase.
- Moodle 4.0 uses `get_default_table_aliases()` and `add_columns_from_entity()`. Moodle 4.1 and later use `get_default_tables()` and `add_all_from_entities()`.
- `lib.php` aliases `lang_string` and `context` on Moodle 4.0, where those classes are not namespaced yet.
- GitHub Actions: `ci.yml` (Moodle 5.2, PostgreSQL and MariaDB), `ci-compat.yml` (4.0 through 5.2), `ci-security.yml`. Postgres health checks use `pg_isready -U postgres`.

## Upgrade

Copy the plugin in place and open **Site administration / Notifications**, or run:

```bash
php admin/cli/upgrade.php
```

On Moodle 5.1 and later the CLI lives at `php public/admin/cli/upgrade.php`.

No database tables are created or changed. There is no `db/upgrade.php` savepoint for this release.
